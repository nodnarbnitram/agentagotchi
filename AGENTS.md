- Preserve the privacy boundary for telemetry and host→bridge status: hooks and status events may contain only task IDs, safe titles, generic state/reason, counts, and timestamps. Never persist, log, or transmit prompts, commands, tool payloads, transcripts, full paths, Wi-Fi credentials, tokens, or private keys unless a later explicit, versioned control path requires a narrowly scoped field.
- Authority is phased, not frozen at v1. Shipping surface today is status display plus focus of a validated canonical UUID. Intended product direction includes device→agent controls (approve/deny and later microphone STT dictation). New mutating or audio control paths are allowed only as deliberate PROTOCOL-versioned features with host capability gating, auth, and tests—do not treat the old focus-only rule as a permanent ban, and do not add those paths silently inside multi-host refactors.
- Read `docs/PROTOCOL.md` before changing WSS messages, provisioning, authentication, focus, or any device→bridge control action; update host and firmware implementations together and bump protocol/versioning when adding actions beyond focus.
- Prefer capability-based, fail-closed device actions: validate id, resolve the owning task/source, dispatch only a registered host capability, acknowledge only on exact success. No silent fallback that opens the wrong host app.
- Multi-host sequencing: semantic core and safer focus first; Pi status-only next; approve/deny and STT are later milestones, not blockers for Pi status. (The original `HANDOFF.md` brief was removed after the rebuild shipped; durable decisions live in `docs/adr/`.)
- Treat `assets/source/pet_base.png` as the artwork source of truth. Run `make assets` after artwork or generator changes and commit every changed generated desktop, firmware, and plugin asset.
- Do not edit ignored ESP-IDF output (`firmware/build/`, `firmware/managed_components/`, `firmware/sdkconfig`). Keep `firmware/main/idf_component.yml` and `firmware/dependencies.lock` aligned when changing firmware dependencies.
- Treat `release/firmware/` as a versioned flash bundle: refresh its binaries, lock, hashes, and `BUILD.md` together; never hand-edit binary artifacts or checksums.
- Run `make test` for source changes; also run `idf.py -C firmware build` for firmware changes when ESP-IDF 5.5.x is active. Record physical-kit results only in `docs/HARDWARE_ACCEPTANCE.md`, never from compilation alone.
- Do not run installation, flashing, or provisioning commands (`scripts/install-macos.sh`, `make provision-env`, or `codex-pet provision`) without explicit user authorization. Provisioning must keep credentials on stdin and out of output.
